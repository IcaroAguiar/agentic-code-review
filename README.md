# Agentic Code Review

Agentic Code Review is an installable agent skill plus a deterministic review toolbelt for code generated by AI agents.

It is designed for the moment before an agent says "done", "fixed", "PR-ready", or "merge-ready". The core idea is simple: static scans are useful evidence, but they are not approval. The final gate should combine a deterministic review packet, runtime proof of the changed behavior, and one independent cold review pass.

## Installation

### Install with npx

After the package is published to npm:

```bash
npx agentic-code-review install
```

By default this installs the skill into:

```text
~/.agents/skills/agentic-code-review
```

For Codex-style skill directories:

```bash
npx agentic-code-review install --target codex
```

That installs into:

```text
~/.codex/skills/agentic-code-review
```

Use a custom directory:

```bash
npx agentic-code-review install --dest ~/.agents/skills
```

Replace an existing installation:

```bash
npx agentic-code-review install --force
```

Restart your agent runtime after installing so the skill can be discovered.

### Install from GitHub with a skill installer

If your agent runtime supports installing skills from GitHub, use the skill path:

```bash
skills/agentic-code-review
```

Example with a GitHub skill installer:

```bash
python ~/.codex/skills/.system/skill-installer/scripts/install-skill-from-github.py \
  --repo <owner>/agentic-code-review \
  --path skills/agentic-code-review
```

### Use without installing the skill

You can run the collector directly from the package:

```bash
npx agentic-code-review collect --base origin/main
```

or from a clone:

```bash
node skills/agentic-code-review/scripts/collect-review-context.mjs --base origin/main
```

## CLI Commands

### `agentic-code-review install`

Copies the skill folder into an agent skill directory.

Options:

- `--target agents`: install into `~/.agents/skills`. This is the default.
- `--target codex`: install into `~/.codex/skills`.
- `--dest <dir>`: install into a custom skills directory.
- `--force`: replace an existing `agentic-code-review` skill directory.

Examples:

```bash
npx agentic-code-review install
npx agentic-code-review install --target codex
npx agentic-code-review install --dest ~/.agents/skills --force
```

### `agentic-code-review collect`

Runs the deterministic review collector from the current repository.

Examples:

```bash
npx agentic-code-review collect
npx agentic-code-review collect --base origin/main
npx agentic-code-review collect --base origin/main --json
npx agentic-code-review collect --root ../api --root ../web
npx agentic-code-review collect --base <base-sha> --head <head-sha>
```

This command prints a review packet with:

- changed repositories and files;
- path-based risk signals;
- deterministic findings;
- normalized gate summary;
- user input checkpoints;
- runtime verification requirements;
- optional external toolbelt inventory or results;
- reviewer instructions.

The collector intentionally reports signals, not proof. A finding should be verified against the actual code before becoming a final review comment.

Important options:

- `--json`: emits a structured packet for CI, dashboards, or calibration.
- `--config <file>`: uses an explicit config file instead of auto-discovering `.agentic-reviewrc.json`.
- `--run-external-tools`: runs installed optional scanners.
- `--allow-tool-downloads`: permits `npx` or `uvx` fallback tools. This is opt-in.
- `--external-tool <name>`: limits optional scanning to one or more named tools.
- `--external-tool-timeout-ms <ms>`: controls timeout for optional tools.

### `.agentic-reviewrc.json`

Projects can tune the deterministic packet without forking the skill. Copy `skills/agentic-code-review/templates/agentic-reviewrc.example.json` to `.agentic-reviewrc.json`.

Supported fields:

- `rules`: enable or disable specific rule ids.
- `severities`: override rule severity to `low`, `medium`, or `high`.
- `thresholds`: tune file size, function length, import count, refactor, and constructor-width thresholds.
- `ignorePaths`: ignore generated or project-specific paths using simple glob-like patterns.
- `customQuestions`: add project/business checkpoints to every packet.
- `customDomainQuestions`: add project-defined domain catalogs without changing the skill.
- `domainCatalogs`: add built-in LGPD/privacy, finance, or health review checkpoints.
- `appType`: tune adaptive thresholds for `monolith`, `microservice`, `public-api`, `frontend`, or `library`.
- `dastTargets`: staging URLs for explicit OWASP ZAP baseline scans.
- `performanceTargets`: URLs for explicit `autocannon`/`wrk` load smoke runs.
- `a11yTargets`: rendered UI URLs for explicit axe accessibility scans.
- `graphqlBaseSchema` / `graphqlHeadSchema`: schema paths for explicit GraphQL Inspector compatibility checks.
- `bundleStatsPath`: stats file path for explicit bundle analysis.
- `externalToolTimeoutMs`: set the default optional tool timeout for that repository.

### `agentic-code-review calibrate`

Runs the collector against historical commit ranges and produces a report for comparing the packet against human reviews or known post-merge bugs.

```bash
npx agentic-code-review calibrate --repo . --case pr-101:<base-sha>:<head-sha>
npx agentic-code-review calibrate --repo . --cases-file calibration-cases.json --json
```

Use calibration to tune false positives, false negatives, and severity mismatches before changing generic rules.

### `agentic-code-review smoke`

Runs the fixture smoke suite for the skill and scripts:

```bash
npx agentic-code-review smoke
```

The smoke suite creates temporary Git repositories under `/private/tmp/agentic-code-review-smoke` and verifies scanner behavior for core cases such as SQL injection, N+1, unbounded list queries, REST/API design, GraphQL/gRPC/WebSocket boundaries, observability/resilience, UI semantics/accessibility, UI performance, architecture boundaries, patch semantics, public contract leaks, UI token validation, large-file signals, cross-repo contracts, historical `--base/--head` ranges, and optional tool selection.

It also validates JSON output, project config behavior, domain catalogs, and generic web/runtime/OWASP security signals such as unsafe HTML sinks, command injection, path traversal, weak crypto, permissive CORS, unsafe cookies, SSRF, open redirects, uploads, webhook signatures, retry/backoff gaps, and sensitive-data logging.

## The Skill

`skills/agentic-code-review/SKILL.md` is the agent-facing workflow.

It instructs an agent to:

1. inspect the user request, plan, review feedback, and diff;
2. run the deterministic collector;
3. treat the collector output as evidence, not approval;
4. run the real production code path touched by the change whenever feasible;
5. resolve context-dependent checkpoints before turning them into blockers;
6. send the packet and evidence to one independent reviewer, subagent, or fresh-context review pass;
7. fix blocking findings;
8. re-run focused verification;
9. only then claim complete, PR-ready, or merge-ready.

## Deterministic Collector

`collect-review-context.mjs` is a language-agnostic Git diff scanner. It does not need project-specific configuration for common cases.

It detects changed Git repositories by walking from the current directory or from explicit `--root` values. It compares changed files against a merge base, staged changes, unstaged changes, and untracked files.

### Important Options

```bash
node skills/agentic-code-review/scripts/collect-review-context.mjs
```

Run from the current Git repository.

```bash
node skills/agentic-code-review/scripts/collect-review-context.mjs --base origin/main
```

Compare the current branch/worktree to `origin/main`.

```bash
node skills/agentic-code-review/scripts/collect-review-context.mjs --root ../api --root ../web
```

Build a cross-repo review packet.

```bash
node skills/agentic-code-review/scripts/collect-review-context.mjs --base <base-sha> --head <head-sha>
```

Review a historical PR, merge commit, or commit range without relying on the current checkout.

```bash
node skills/agentic-code-review/scripts/collect-review-context.mjs --run-external-tools
```

Run installed optional tools in addition to the built-in scanner.

```bash
node skills/agentic-code-review/scripts/collect-review-context.mjs \
  --run-external-tools \
  --external-tool jscpd \
  --external-tool-timeout-ms 30000
```

Run a selected optional tool with a custom timeout.

```bash
node skills/agentic-code-review/scripts/collect-review-context.mjs \
  --run-external-tools \
  --allow-tool-downloads
```

Permit fallback tools that download through `npx` or `uvx`. This is intentionally opt-in.

## Built-In Review Signals

The collector currently checks for:

- raw SQL and interpolated SQL injection risk;
- N+1 and per-item query patterns;
- unbounded list/query access without visible limit, pagination, cursor, or batch boundary;
- read-then-write without obvious transaction, lock, or idempotency guard;
- external side effects inside transactions;
- public/API response mappers that expose raw, internal, legacy, or domain state without sanitization;
- REST/API route design signals: verb-oriented paths, unsafe GET mutation signals, mutation status-code ambiguity, collection routes without pagination/filter contracts, and public routes without visible versioning strategy;
- GraphQL/gRPC/WebSocket signals: resolver N+1 or unbounded reads, mutations without boundary controls, subscriptions without scope/backpressure, production introspection signals, protobuf compatibility/versioning gaps, and realtime handlers without auth/backpressure;
- UI semantic and accessibility signals: missing image alternatives, unlabeled inputs, clickable divs without keyboard semantics, link/button semantic drift, and page/layout files with many divs but no landmarks;
- advanced accessibility signals: positive tabindex, ARIA misuse, missing focus-visible replacement, and missing skip links for repeated navigation;
- observability/resilience signals: unstructured error logs without correlation IDs, security events without audit/metrics, external calls without timeout/retry/circuit-breaker policy, and critical boundaries without instrumentation signals;
- UI performance signals: network-on-input without debounce/cancellation, blocking render work, and heavy dependencies without bundle-budget evidence;
- architecture boundary signals: domain imports from outer/framework layers, presentation importing data/persistence directly, missing port/interface boundaries, and UI mixing rendering with direct data access;
- public response types that reuse broad internal/domain/persistence types;
- weak string-only validation for runtime-controlling config, visual tokens, statuses, roles, URLs, modes, and provider values;
- asymmetric defaults or normalization for configurable runtime objects;
- unsafe typing, broad casts, and `any`-style patterns;
- swallowed errors, debug artifacts, and direct console warnings in production flows;
- masked error UI where `catch` returns `null` while the component still depends on `isError`;
- patch builders that conflate `undefined` with no-change;
- deep merges without explicit removal/delete/tombstone semantics;
- missing reset/removal/null/undefined coverage for patch semantics;
- preview/settings components that pass structural editing callbacks into read-only surfaces;
- simulated icon library contracts that expose library names while rendering one internal path;
- enum-like API fields without membership normalization;
- unsanitized CSS/branding tokens flowing into inline styles or CSS variables;
- background/color fields carrying gradient/image semantics;
- static imports of commonly heavy UI/runtime libraries from route/page/layout/shell files without lazy/dynamic boundaries;
- local paths, localhost URLs, and machine-specific literals;
- skipped or focused tests;
- mock-heavy tests without real production boundary execution;
- happy-path-only test changes;
- stale or orphaned mocks that no longer match changed production imports;
- backend boundary changes without e2e/integration evidence;
- cross-repo contract changes without consumer compatibility checks;
- package manifest and lockfile drift;
- large files, long functions, high import coupling, deep nesting, broad constructors, and single-responsibility refactor gates.

## Normalized Gate Categories

Findings are normalized into five categories:

- `blocking`: should be fixed or explicitly justified before approval.
- `review-signal`: needs human/agent judgment and context.
- `runtime-required`: exact production path proof is needed.
- `user-input-checkpoint`: the reviewer should ask before treating the concern as blocking.
- `informational`: useful context only.

This distinction is important. For example, N+1 risk and public contract leakage are strong signals, while code-splitting and large-file warnings are usually review signals unless they explain a concrete regression.

## Runtime Verification

The skill is strict about runtime proof. Static scans, lint, typecheck, build, or command dumps are not enough for executable behavior changes.

Good evidence names the real production path exercised:

- function;
- class;
- handler;
- route;
- hook;
- adapter;
- command;
- repository/query path;
- browser flow.

For UI/browser changes, use the QA evidence contract in:

```text
skills/agentic-code-review/templates/qa-evidence.md
```

## Templates

The templates are examples and starting points, not mandatory framework dependencies.

### `qa-evidence.md`

Minimum evidence format for browser, UI, CLI, desktop, authenticated smoke, and visual behavior validation.

Use it to record:

- flow tested;
- surface and environment;
- credential lookup;
- initial state;
- actions performed;
- observed result;
- screenshot or video path;
- deterministic test/probe;
- bugs found or `No bug observed.`

### `n-plus-one-query-test.vitest.ts`

Example test shape for proving query count stays bounded as input size grows.

Use it when the review packet reports:

- `possible-n-plus-one-query`;
- `parallel-n-plus-one-query`;
- `sequential-query-in-loop`.

### `concurrency-test.vitest.ts`

Example test shape for concurrent calls against the same resource.

Use it when the code performs:

- read-then-write;
- duplicate creation risk;
- concurrent update risk;
- uniqueness/idempotency-sensitive writes.

### `idempotency-test.vitest.ts`

Example test shape for proving repeated commands or requests do not duplicate side effects.

Use it for:

- payment/integration calls;
- queue jobs;
- import flows;
- webhook handlers;
- retryable commands.

### `transaction-rollback-test.vitest.ts`

Example test shape for proving partial failures roll back correctly.

Use it when a change touches:

- transactions;
- persistence plus side effects;
- multi-step writes;
- migration-adjacent behavior.

### `validation-boundary-test.vitest.ts`

Example test shape for proving invalid input is rejected at the boundary and valid input still passes.

Use it for:

- DTO/schema changes;
- public API contracts;
- command input;
- visual/runtime configuration tokens.

### `rest-api-contract-test.vitest.ts`

Example test shape for proving REST method semantics, status codes, pagination, filters, and resource-oriented routes through the real HTTP boundary.

### `graphql-boundary-test.vitest.ts`

Example test shape for proving GraphQL auth, pagination/complexity limits, DataLoader/batching, and bounded resolver query count.

### `realtime-protocol-test.vitest.ts`

Example test shape for WebSocket/subscription authorization, scoped delivery, disconnect cleanup, and backpressure-sensitive behavior.

### `observability-resilience-test.vitest.ts`

Example test shape for timeout/retry/circuit-breaker behavior plus safe logs, metrics, and correlation identifiers.

### `openapi-compatibility-test.vitest.ts`

Example test shape for proving generated or checked-in OpenAPI contracts document the changed public route, status codes, parameters, and error responses.

### `ui-semantic-a11y-test.vitest.ts`

Example test shape for semantic landmarks, labels, image alternatives, button/link semantics, and automated accessibility checks.

### `layer-boundary-test.vitest.ts`

Example test shape for proving application/domain boundaries through ports or fakes without importing concrete persistence/framework layers.

### `calibration-2026-04-28.md`

Template for recording scanner calibration against real historical PRs or merge windows.

Use it when tuning rules to reduce false positives or catch false negatives.

## Development

Run the smoke suite:

```bash
npm run smoke
```

Run the collector locally:

```bash
npm run collect -- --base origin/main
```

Run the CLI from the checkout:

```bash
node bin/agentic-code-review.mjs help
node bin/agentic-code-review.mjs smoke
node bin/agentic-code-review.mjs collect --base origin/main
```

## Publishing

Before publishing:

1. Run `npm run smoke`.
2. Run `npm pack --dry-run`.
3. Confirm no private paths, credentials, local policy files, or internal repositories are packaged.
4. Publish with:

```bash
npm publish --access public
```

After publishing, users can install with:

```bash
npx agentic-code-review install
```
